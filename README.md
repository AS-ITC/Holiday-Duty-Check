# ตรวจเวรวันหยุด — ระบบตรวจเวรและจัดการ Master

แอปนี้ทำงานได้ 2 โหมด:

- **โหมดระบบกลาง (แนะนำ):** ใช้ Supabase เพื่อให้ผลตรวจ Master และรูปภาพใช้ร่วมกันทุกเครื่อง
- **โหมด Legacy:** ใช้ `server.py` และ SQLite สำหรับการทดสอบภายในเครื่องเท่านั้น

## เปิดใช้งานระบบกลางด้วย Supabase (แนะนำสำหรับ GitHub Pages)

1. เปิดไฟล์ `supabase-schema.sql` ใน Supabase Dashboard → SQL Editor แล้วกด Run
2. สร้างผู้ใช้คนแรกผ่านหน้าเว็บ
3. ใน SQL Editor ตั้งผู้ใช้คนแรกเป็น Superuser และอนุมัติ:

```sql
update public.profiles
set role = 'superuser',
    status = 'approved',
    approved_at = now()
where email = 'อีเมลผู้ดูแลระบบ';
```

4. ใน Supabase Dashboard → Authentication → Providers → Email ให้ปิด **Confirm email** หากต้องการให้การอนุมัติโดย Superuser เป็นขั้นตอนยืนยันเพียงอย่างเดียว
5. Deploy Edge Function สำหรับการตั้งรหัสผ่าน:

```bash
supabase functions deploy account-admin
```

6. เปิดเว็บ GitHub Pages แล้วเข้าสู่ระบบด้วยอีเมลและรหัสผ่าน

สิทธิ์มี 4 ระดับ:

- **User:** ใช้งานตรวจเวรและดูประวัติ
- **Admin:** ใช้งานระบบและจัดการผลตรวจตามสิทธิ์ แต่เปิดหน้าตั้งค่าไม่ได้
- **Poweruser:** เปิดหน้าตั้งค่าและแก้ Master ได้
- **Superuser:** จัดการสิทธิ์ผู้ใช้ อนุมัติผู้สมัคร และตั้งรหัสผ่านใหม่ให้ผู้ใช้ได้

ผู้สมัครใหม่จะมีสถานะรออนุมัติจนกว่า Superuser จะกดอนุมัติใน `ตั้งค่า → ผู้ใช้งาน` รหัสผ่านจะหมดอายุทุก 180 วัน และผู้ใช้จะถูกบังคับให้เปลี่ยนรหัสผ่าน หากลืมรหัสผ่านให้ Superuser กด `ตั้งรหัสผ่านใหม่`

ไฟล์ `supabase-config.js` ใช้เฉพาะ Project URL และ Publishable Key ซึ่งเปิดเผยบนหน้าเว็บได้ ห้ามนำ `service_role key` มาใส่ในไฟล์นี้
Edge Function ใช้ `SUPABASE_SERVICE_ROLE_KEY` เฉพาะฝั่ง Supabase เพื่อไม่ให้คีย์ลับรั่วไปยัง GitHub Pages

รูปภาพใหม่จะถูกบีบอัดและอัปโหลดไปยัง Storage bucket `holiday-photos` แบบ Private ผู้ที่ไม่มีสิทธิ์จะไม่สามารถเปิดรูปโดยตรงได้

หากต้องการทดสอบ Legacy แบบไม่ใช้ Supabase ต้องใช้ Python 3:

```bash
python3 server.py
```

แล้วเปิด `http://127.0.0.1:8765/` ในเบราว์เซอร์ ข้อมูลจะถูกเก็บในไฟล์ `holiday-duty.db` (ไฟล์นี้ถูกยกเว้นไม่ให้ commit เข้า Git) หากต้องการให้เครื่องอื่นในเครือข่ายเชื่อมต่อ ให้รัน `HOST=0.0.0.0 python3 server.py` และเปิดพอร์ต 8765 ตามนโยบายเครือข่ายขององค์กร

- โหมด Legacy ไม่ใช่โหมดระบบกลางสำหรับการใช้งานจริง

## วิธี deploy ครั้งแรก

1. อัปโหลดทั้ง 2 ไฟล์ (`index.html` และ `data.js`) เข้า repo นี้ (root ของ repo หรือโฟลเดอร์ที่ตั้ง GitHub Pages ไว้ให้ตรงกัน)
2. เปิด GitHub Pages / Netlify ให้ deploy จาก repo นี้ (เหมือนที่ทำอยู่แล้ว)
3. เปิดลิงก์เว็บ (เช่น `as-itc.github.io/Holiday-Duty-Check/`) จากมือถือ/คอมได้เลย ไม่ต้องตั้งค่าอะไรเพิ่ม

## วิธีอัปเดตรายชื่อผู้ตรวจ / พื้นที่-โซน (สำหรับ Dev)

แก้ไฟล์ **`data.js`** บน GitHub โดยตรง (กดไอคอนดินสอในหน้าเว็บ GitHub เพื่อแก้ไขได้เลย ไม่ต้องมีเครื่องมืออื่น):

```js
window.MASTER_DATA = {
  members: [
    { id: "m1", name: "ชื่อ-สกุล" }
    // เพิ่ม/ลบ/แก้ตามต้องการ — id ใส่อะไรก็ได้ขอไม่ซ้ำ
  ],
  areas: [
    { id: "a1", location: "SS", zone: "Zone1 - Pilot Plant ชั้น 5 / Office / Meeting Room / ห้องน้ำ / ห้องครัว /ห้อง Lab", order: 1 }
    // order คือลำดับการแสดงโซนภายในพื้นที่ (location) เดียวกัน
  ],
  issueTypes: [
    "น้ำไม่ปิด", "อุปกรณ์ไฟฟ้าถูกเปิดทิ้งไว้", "ลมรั่ว", "สารเคมีรั่วซึม", "สายไฟชำรุด",
    "ไม่ปิดประตู / หน้าต่าง", "พบสัตว์พาหะ", "น้ำรั่วซึม", "ประตูฉุกเฉินถูกเปิดใช้งาน",
    "อื่นๆ", "เครื่องจักรถูกเปิดทิ้งไว้", "สารเคมี", "แก๊สรั่ว"
    // ตัวเลือก "ประเภทปัญหา" ในฟอร์ม เพิ่ม/ลบ/แก้ชื่อได้ตามต้องการ — ใช้ list เดียวกันทุกพื้นที่
  ]
};
```

**หมายเหตุ:** ผู้ตรวจเลือกด้วยชื่ออย่างเดียว ส่วนหน้าจอเลือกพื้นที่/จุดตรวจจะแสดงทุก `location` ที่มีอยู่ใน `areas` ให้ทุกคนเห็นเหมือนกันเสมอ

แก้เสร็จกด commit → รอเว็บ deploy ใหม่ (1-2 นาที) → ทุกคนที่เปิด/รีเฟรชเว็บจะเห็นรายชื่อที่อัปเดตแล้วทันที

หน้าตั้งค่าในแอป (⚙️ → ผู้ตรวจ / พื้นที่-โซน / ประเภทปัญหา) เปิดได้เฉพาะ Poweruser และ Superuser การแก้ไขจะบันทึกใน Master กลาง

## ผลตรวจ (records)

เมื่อเปิดผ่าน `server.py` ผลตรวจที่กรอกและรูปถ่ายจะอยู่ใน SQLite ของเซิร์ฟเวอร์ ทุกเครื่องที่เชื่อมต่อเซิร์ฟเวอร์เดียวกันจึงเห็นประวัติร่วมกันได้ หากเปิดแบบไม่มีเซิร์ฟเวอร์ ผลตรวจจะอยู่ในเครื่องนั้นเท่านั้น

## บันทึกเบิกของสโตร์ / ขนย้ายเครื่องจักร-อะไหล่ (ฟีเจอร์เสริม)

นอกจากปุ่มพื้นที่ตรวจ Zone1-Zone13 แล้ว หน้า "พื้นที่ตรวจ" จะมีการ์ดพิเศษ 2 อันเพิ่มมาให้เสมอ:

- **📦 เบิกของสโตร์** — จดบันทึกตอนมีการเบิกของระหว่างเวร
- **🚚 ขนย้ายเครื่องจักร/อะไหล่** — จดบันทึกตอนมีการขนย้ายเครื่องจักรหรืออะไหล่ระหว่างเวร

ทั้งสองอย่างเป็น **ฟีเจอร์เสริม ไม่บังคับ** — จะมี 0 รายการ หรือกี่รายการก็ได้ในแต่ละเวร ไม่ใช่ checklist ตายตัวแบบโซนตรวจ (การ์ดจะโชว์แค่จำนวนรายการทั้งหมดที่เคยกรอกไว้ ไม่ใช่สถานะรอตรวจ/ตรวจแล้ว) กดที่การ์ดจะเห็นรายการที่เคยบันทึกไว้ทั้งหมด (ทุกวันที่ ไม่ใช่แค่วันนี้) พร้อมปุ่ม ✏️ แก้ไข และ 🗑 ลบ ต่อรายการ — กดปุ่ม "+ เพิ่มรายการ" เพื่อกรอกรายการใหม่ได้เรื่อยๆ ตามที่พบจริงหน้างาน แนบรูปได้เหมือนฟอร์มตรวจพื้นที่ (บีบอัดรูปอัตโนมัติก่อนบันทึกเหมือนกัน)

บันทึกทั้งสองแบบนี้จะไปโผล่ในแท็บ **ประวัติ** ปนกับผลตรวจพื้นที่ (ดูคอลัมน์ "ประเภท" เพื่อแยก) และออก **Excel/PDF** ได้เหมือนกันทุกประการ (คอลัมน์พื้นที่/โซน/ประเภทปัญหา/รายละเอียด/ผู้ปฏิบัติงาน จะโชว์ข้อมูลที่ใกล้เคียงที่สุดของบันทึกประเภทนั้นแทน เช่น พื้นที่ = ฝ่าย, โซน = แผนก)

**ฝ่าย/แผนก ในฟอร์มสองอย่างนี้มาจากไหน?** มาจาก `window.MASTER_DATA.orgList` ใน `data.js` — เป็นรายชื่อฝ่าย/แผนกทั้งบริษัท **คนละรายการกับ `department` ของผู้ตรวจโดยสิ้นเชิง** (ที่ใช้กรองรายชื่อตอนเข้าแอปหน้าแรก) ตั้งใจแยกกันเพราะเป็นคนละบริบท: `department` ของผู้ตรวจ คือแผนกของ**คนที่มาตรวจเวร**, ส่วน `orgList` คือฝ่าย/แผนกของ**เจ้าของเรื่องที่เกี่ยวข้องกับของที่เบิก/เครื่องที่ขนย้าย** ซึ่งอาจเป็นคนละแผนกกับผู้ตรวจเวรเลยก็ได้

**Dev แก้ `orgList` ยังไงถ้ารายชื่อฝ่าย/แผนกเปลี่ยน?** แก้ไฟล์ `data.js` บน GitHub เหมือนส่วนอื่น เพิ่ม/ลบ/แก้ไอเทมใน array `window.MASTER_DATA.orgList` แต่ละไอเทมมีแค่ 2 ฟิลด์:

```js
orgList: [
  { faction: "ชื่อฝ่าย", dept: "ชื่อแผนกในฝ่ายนั้น" },
  { faction: "ชื่อฝ่าย", dept: "ชื่อแผนกอีกอันในฝ่ายเดียวกัน" },
  // ฝ่ายเดียวกันใส่ได้หลายแถว (แผนกต่างกัน) — dropdown "แผนก" ในฟอร์มจะกรองจาก faction
  // ที่เลือกไว้อัตโนมัติ ลำดับที่โชว์ในทั้ง 2 dropdown จะเรียงตามลำดับที่ปรากฏในไฟล์นี้เป๊ะๆ
  // (ไม่ได้เรียง ก-ฮ ให้เอง) เพิ่ม/ลบ/สลับตำแหน่งได้ตามต้องการ
]
```

แก้เสร็จ commit เหมือนเดิม รอเว็บ deploy ใหม่ (1-2 นาที) แล้วทุกคนจะเห็น dropdown ฝ่าย/แผนกชุดใหม่ในฟอร์มทั้งสองทันที

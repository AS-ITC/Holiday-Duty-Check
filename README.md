# ตรวจเวรวันหยุด (เวอร์ชันออฟไลน์) — repo สำหรับ deploy

แอปนี้**ไม่มีเซิร์ฟเวอร์/ฐานข้อมูลใด ๆ** และใช้แค่ **GitHub ที่เดียว** ไม่ต้องเชื่อมกับระบบอื่นเลย (ไม่มี Firebase, ไม่มี Cloudflare):

- ผลตรวจ + รูปถ่าย เก็บอยู่ในเบราว์เซอร์ของเครื่องที่กดบันทึกเท่านั้น (IndexedDB) — ไม่แชร์ข้ามเครื่อง
- รายชื่อผู้ตรวจ + พื้นที่/โซน ("master data") มาจากไฟล์ **`data.js`** ที่วางอยู่ข้าง ๆ `index.html` — ทุกคนที่เปิดเว็บเห็นรายการชุดเดียวกัน แก้ได้เฉพาะ **Dev** เท่านั้น โดยแก้ไฟล์นี้บน GitHub โดยตรง

## วิธี deploy ครั้งแรก

1. อัปโหลดทั้ง 2 ไฟล์ (`index.html` และ `data.js`) เข้า repo นี้ (root ของ repo หรือโฟลเดอร์ที่ตั้ง GitHub Pages ไว้ให้ตรงกัน)
2. เปิด GitHub Pages / Netlify ให้ deploy จาก repo นี้ (เหมือนที่ทำอยู่แล้ว)
3. เปิดลิงก์เว็บ (เช่น `as-itc.github.io/Holiday-Duty-Check/`) จากมือถือ/คอมได้เลย ไม่ต้องตั้งค่าอะไรเพิ่ม

## วิธีอัปเดตรายชื่อผู้ตรวจ / พื้นที่-โซน (สำหรับ Dev)

แก้ไฟล์ **`data.js`** บน GitHub โดยตรง (กดไอคอนดินสอในหน้าเว็บ GitHub เพื่อแก้ไขได้เลย ไม่ต้องมีเครื่องมืออื่น):

```js
window.MASTER_DATA = {
  members: [
    { id: "m1", name: "ชื่อ-สกุล" }
    // เพิ่ม/ลบ/แก้ตามต้องการ — id ใส่อะไรก็ได้ขอไม่ซ้ำ — ไม่มี field แผนกแล้ว มีแค่ชื่ออย่างเดียว
  ],
  areas: [
    { id: "a1", location: "Zone1", zone: "Pilot Plant ชั้น 5", order: 0 }
    // order คือลำดับการแสดงจุดย่อยภายใน location (ZoneN) เดียวกัน
  ],
  issueTypes: [
    "น้ำไม่ปิด", "อุปกรณ์ไฟฟ้าถูกเปิดทิ้งไว้", "ลมรั่ว", "สารเคมีรั่วซึม", "สายไฟชำรุด",
    "ไม่ปิดประตู / หน้าต่าง", "พบสัตว์พาหะ", "น้ำรั่วซึม", "ประตูฉุกเฉินถูกเปิดใช้งาน",
    "อื่นๆ", "เครื่องจักรถูกเปิดทิ้งไว้", "สารเคมี", "แก๊สรั่ว"
    // ตัวเลือก "ประเภทปัญหา" ในฟอร์ม เพิ่ม/ลบ/แก้ชื่อได้ตามต้องการ — ใช้ list เดียวกันทุกพื้นที่
  ]
};
```

**หมายเหตุ:** หน้าแรกของแอป **ไม่มีให้เลือกแผนกแล้ว และฐานข้อมูลผู้ตรวจก็ไม่มี field แผนกอีกต่อไป** — พิมพ์ค้นหาชื่อผู้ตรวจได้จากรายชื่อทั้งหมดใน `members` ตรงๆ เลย ส่วน `location` ของพื้นที่ (areas) เป็นคนละเรื่องกับผู้ตรวจอยู่แล้ว — หน้าจอเลือกพื้นที่/จุดตรวจจะแสดง**ทุก location ที่มีอยู่ใน `areas`** ให้ทุกคนเห็นเหมือนกันเสมอ

แก้เสร็จกด commit → รอเว็บ deploy ใหม่ (1-2 นาที) → ทุกคนที่เปิด/รีเฟรชเว็บจะเห็นรายชื่อที่อัปเดตแล้วทันที

หน้าตั้งค่าในแอป (⚙️ → ผู้ตรวจ / พื้นที่-โซน / ประเภทปัญหา) ยังให้พนักงานทั่วไปเพิ่ม/ลบรายการดูตัวอย่างในเครื่องตัวเองได้ แต่การเพิ่ม/ลบนั้นเป็นแค่ชั่วคราว (หายไปเมื่อรีโหลดหน้า) ไม่กระทบคนอื่น — ถ้าอยากได้ list ปัจจุบันไปอ้างอิงตอนแก้ `data.js` มีปุ่ม "ดาวน์โหลดรายการปัจจุบัน" ให้ในหน้าตั้งค่า

## ผลตรวจ (records)

ผลตรวจที่พนักงานกรอกจะอยู่ในเครื่องของคนกรอกเท่านั้น ไม่ได้อยู่ใน repo และไม่มีใครเห็นร่วมกัน — ถ้าต้องการสรุปรวม ให้แต่ละคนกด "ออกรายงาน PDF" หรือ "ส่งออก Excel" ในแท็บประวัติแยกทีละไฟล์ก็ได้ (Excel มีคอลัมน์รูปภาพแนบฝังอยู่ในไฟล์ให้เลย เปิดดูได้ใน Excel/Google Sheets/LibreOffice) หรือกด "📧 ส่ง PDF + Excel ทางอีเมล" ทีเดียวเพื่อสร้างทั้ง 2 ไฟล์พร้อมกันแล้วส่งอีเมล — บนมือถือที่รองรับ Web Share จะเปิดหน้าต่างแชร์พร้อมไฟล์แนบทั้ง 2 ไฟล์ให้เลือกแอปอีเมลได้ทันที ส่วนบนคอมพิวเตอร์ (ที่เบราว์เซอร์ไม่รองรับการแนบไฟล์อัตโนมัติ) จะดาวน์โหลดทั้ง 2 ไฟล์ให้ แล้วเปิดดราฟต์อีเมลเตือนให้แนบไฟล์เอง

## บันทึกเพิ่มเติม 4 แบบ (ฟีเจอร์เสริม)

นอกจากปุ่มพื้นที่ตรวจ Zone1-Zone13 แล้ว หน้า "พื้นที่ตรวจ" จะมีการ์ดพิเศษ 4 อันเพิ่มมาให้เสมอ:

- **📦 เบิกของสโตร์** — จดบันทึกตอนมีการเบิกของระหว่างเวร
- **🚚 ขนย้ายเครื่องจักร/อะไหล่** — จดบันทึกตอนมีการขนย้ายเครื่องจักรหรืออะไหล่ระหว่างเวร
- **🚑 รายงานการเกิดอุบัติเหตุ** — บันทึกสถานที่เกิดเหตุ/ผู้ประสบเหตุ/หน่วยงาน/รายละเอียดเหตุการณ์/ผู้รับทราบ (หัวหน้างาน-จป.-ผู้บริหาร) และเลือกผลกระทบ (ไม่มีผู้บาดเจ็บ / บาดเจ็บเล็กน้อย / บาดเจ็บต้องพบแพทย์ / อื่นๆ ระบุเอง)
- **👷 ผู้รับเหมาขอเข้าพื้นที่ (นอกแผน)** — บันทึกบริษัท/ผู้ประสานงาน/จำนวนผู้เข้าปฏิบัติงาน/พื้นที่ปฏิบัติงาน/วัตถุประสงค์การเข้าพื้นที่

ทั้ง 4 อย่างเป็น **ฟีเจอร์เสริม ไม่บังคับ** — จะมี 0 รายการ หรือกี่รายการก็ได้ในแต่ละเวร ไม่ใช่ checklist ตายตัวแบบโซนตรวจ (การ์ดจะโชว์แค่จำนวนรายการทั้งหมดที่เคยกรอกไว้ ไม่ใช่สถานะรอตรวจ/ตรวจแล้ว) กดที่การ์ดจะเห็นรายการที่เคยบันทึกไว้ทั้งหมด (ทุกวันที่ ไม่ใช่แค่วันนี้) พร้อมปุ่ม ✏️ แก้ไข และ 🗑 ลบ ต่อรายการ — กดปุ่ม "+ เพิ่มรายการ" เพื่อกรอกรายการใหม่ได้เรื่อยๆ ตามที่พบจริงหน้างาน แนบรูปได้เหมือนฟอร์มตรวจพื้นที่ (บีบอัดรูปอัตโนมัติก่อนบันทึกเหมือนกัน)

บันทึกทั้ง 4 แบบนี้จะไปโผล่ในแท็บ **ประวัติ** ปนกับผลตรวจพื้นที่ (ดูคอลัมน์ "ประเภท" เพื่อแยก) และออก **Excel/PDF** ได้เหมือนกันทุกประการ (คอลัมน์พื้นที่/โซน/ประเภทปัญหา/รายละเอียด/ผู้ปฏิบัติงาน จะโชว์ข้อมูลที่ใกล้เคียงที่สุดของบันทึกประเภทนั้นแทน เช่น เบิกของสโตร์/ขนย้ายเครื่องจักร → พื้นที่ = ฝ่าย, โซน = แผนก; รายงานอุบัติเหตุ → พื้นที่ = สถานที่เกิดเหตุ, โซน = หน่วยงาน, ประเภทปัญหา = ผลกระทบ; ผู้รับเหมาเข้าพื้นที่ → พื้นที่ = พื้นที่ปฏิบัติงาน, โซน = บริษัท)

**ฝ่าย/แผนก ในฟอร์ม "เบิกของสโตร์"/"ขนย้ายเครื่องจักร" มาจากไหน?** มาจาก `window.MASTER_DATA.orgList` ใน `data.js` — เป็นรายชื่อฝ่าย/แผนกทั้งบริษัท ใช้เฉพาะ 2 ฟอร์มนี้เท่านั้น (ฟอร์มรายงานอุบัติเหตุ/ผู้รับเหมาเข้าพื้นที่ไม่มีดรอปดาวน์ฝ่าย/แผนก เพราะเป็นฟิลด์อิสระตามแบบฟอร์มกระดาษเดิม)

**Dev แก้ `orgList` ยังไงถ้ารายชื่อฝ่าย/แผนกเปลี่ยน?** แก้ไฟล์ `data.js` บน GitHub เหมือนส่วนอื่น เพิ่ม/ลบ/แก้ไอเทมใน array `window.MASTER_DATA.orgList` แต่ละไอเทมมีแค่ 2 ฟิลด์:

```js
orgList: [
  { faction: "ชื่อฝ่าย", dept: "ชื่อแผนกในฝ่ายนั้น" },
  { faction: "ชื่อฝ่าย", dept: "ชื่อแผนกอีกอันในฝ่ายเดียวกัน" },
  // ฝ่ายเดียวกันใส่ได้หลายแถว (แผนกต่างกัน) — dropdown "แผนก" ในฟอร์มจะกรองจาก faction
  // ที่เลือกไว้อัตโนมัติ ลำดับที่โชว์ในทั้ง 2 dropdown จะเรียงตามลำดับที่ปรากฏในไฟล์นี้เป๊ะๆ
  // (ไม่ได้เรียง ก-ฮ ให้เอง) เพิ่ม/ลบ/สลับตำแหน่งได้ตามต้องการ
]
```

แก้เสร็จ commit เหมือนเดิม รอเว็บ deploy ใหม่ (1-2 นาที) แล้วทุกคนจะเห็น dropdown ฝ่าย/แผนกชุดใหม่ในฟอร์มทั้งสองทันที
